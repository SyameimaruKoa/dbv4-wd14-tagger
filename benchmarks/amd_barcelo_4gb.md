# AMD Barcelo 4 GiB WebGPU測定と512 MiB比較（2026-09-22）

[512 MiB時の記録](amd_barcelo_512mb.md)と同じ PC、スクリプト、合成画像、batch size 1、warmup 3回、各経路10回で測定した。生データは [amd_barcelo_4gb.json](amd_barcelo_4gb.json)。表の速度は各10回の中央値。推論のみは前処理済み入力の `session.run`、前処理込みは `predict_images` を計時し、モデル取得・起動・XMP・レポート生成は含めない。

## 環境

- Ubuntu 26.04.1、kernel 7.0.0-31-generic、Ryzen 5 7530U内蔵 Radeon Graphics（PCI 1002:15e7）、ONNX Runtime 1.30.0、WebGPU EP 0.3.0、Python 3.13.15。
- 専用 VRAM 4,096 MiB、GTT上限約5,897 MiB、物理 RAM約11,794 MiB。512 MiB設定時の物理 RAM約15,322 MiBから、専用 VRAM割当分だけ利用可能な物理 RAMが減った。
- メモリは各モデルを独立プロセスで起動し、50 ms間隔で amdgpu の専用 VRAM・GTT 使用量と子プロセスの RSS をサンプリングした。VRAM/GTT はシステム全体の値であり、増分は各モデルの測定直前とピークの差。RSSはプロセスの常駐ページであり、GPUメモリ量とは別の指標。

| モデル | 専用 VRAM 開始→ピーク MiB（増分） | GTT 開始→ピーク MiB（増分） | プロセス RAM ピーク RSS MiB | 推論のみ ms/枚 | 前処理込み ms/枚 |
| --- | ---: | ---: | ---: | ---: | ---: |
| lightweight | 463.7→764.5（+300.8） | 89.3→94.8（+5.4） | 393.6 | 74.2 | 84.9 |
| balanced | 463.7→1,116.2（+652.5） | 87.3→98.8（+11.5） | 936.3 | 617.5 | 639.2 |
| high | 463.7→2,145.5（+1,681.8） | 89.3→110.8（+21.5） | 2,196.2 | 3,639.0 | 3,657.0 |
| ultra | 557.2→3,926.7（+3,369.5） | 95.3→161.1（+65.7） | 257.8 | 5,194.3 | 5,226.1 |
| wd14_v3 | 476.3→1,425.3（+949.0） | 97.3→100.8（+3.5） | 646.0 | 804.3 | 819.1 |

専用 VRAM のピーク使用率は順に 18.7%、27.3%、52.4%、95.9%、34.8%。5モデルとも active provider は `WebGpuExecutionProvider` と `CPUExecutionProvider`。測定プロセスの swap は全モデルで0 MiB、システム全体でも最大約5 MiBだった。`ultra` は batch size 1 でも専用 VRAMの約96%に達したため、batch size 4での動作余裕は確認していない。

## 512 MiBとの速度比較

| モデル | 推論のみ 512 MiB → 4 GiB | 短縮率 | 前処理込み 512 MiB → 4 GiB |
| --- | ---: | ---: | ---: |
| lightweight | 91.1 → 74.2 ms/枚 | 18.6% | 107.0 → 84.9 ms/枚 |
| balanced | 729.8 → 617.5 ms/枚 | 15.4% | 747.6 → 639.2 ms/枚 |
| high | 4,173.6 → 3,639.0 ms/枚 | 12.8% | 4,197.0 → 3,657.0 ms/枚 |
| ultra | 5,559.2 → 5,194.3 ms/枚 | 6.6% | 5,561.0 → 5,226.1 ms/枚 |
| wd14_v3 | 872.1 → 804.3 ms/枚 | 7.8% | 885.0 → 819.1 ms/枚 |

短縮率は `1 - (4 GiB時の中央値 / 512 MiB時の中央値)`。512 MiB時に主にGTTへ置かれたモデルデータが、4 GiB時には主に専用VRAMへ移った。単一の合成画像・各10回・各設定1セットの測定であり、温度、電源状態、再起動によるキャッシュやメモリ状態の差も含む。速度差をVRAM設定だけの因果効果と断定しない。512 MiB時の `ultra` はシステムswapが約6.6 GiBまで増えたため、特に比較条件が異なる。

## 検証範囲

WebGPUの通常起動経路でも `lightweight` の合成PNG1枚の推論とタグ書き込みが成功した。`compact_manual` と `medium_manual` はリポジトリ管理者の承認待ち、`future_1b` はONNX未公開のため、両VRAM設定とも測定対象外。実画像でのタグ品質と大量画像の持続性能は未検証。
